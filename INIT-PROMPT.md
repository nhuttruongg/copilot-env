# INIT-PROMPT — Khởi tạo Copilot Agentic Environment

## Cách dùng

1. **Copy `.github/`** từ repo này vào dự án của bạn:
   ```bash
   cp -r .github /path/to/your-project/
   ```
2. **Mở Copilot Chat** ở chế độ **Agent mode**
3. **Paste toàn bộ nội dung bên dưới** (từ dòng `---` trở đi) vào chat
4. Chạy **1 lần duy nhất** cho mỗi dự án — idempotent, chạy lại cũng an toàn.

> **Yêu cầu:** Python 3.10+ và git. Nếu thiếu, bootstrap sẽ báo lỗi rõ ràng.

---

You are activating a full agentic development environment for this project. Execute the following steps in order. Do not stop between steps or ask "should I continue?" — run everything continuously until the final ready report.

## Step 1 — Bootstrap

Run the bootstrap script. It auto-detects the project profile (tiny/small/medium/large/xlarge), creates the cache directory, and builds the code graph.

```bash
bash .github/tools/bootstrap.sh
```

Capture the full output. If bootstrap fails:
- `python3 not found` → stop and report: user needs Python 3.10+
- `git not found` → stop and report: user needs git
- `tree-sitter install failed` → continue; graph will be disabled — note this in the final report
- Any other error → show the full error and stop

## Step 2 — Analyze the Codebase

Read whatever exists (skip what doesn't):

**Package manifests** (detect tech stack):
- `package.json`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`
- `pyproject.toml`, `setup.py`, `requirements.txt`, `Pipfile`
- `Cargo.toml`, `go.mod`, `pom.xml`, `build.gradle`, `*.csproj`

**Entry points** (understand the project):
- `README.md` (or `README.rst`, `readme.md`)
- `src/index.ts`, `src/main.ts`, `src/app.ts`
- `main.py`, `app.py`, `src/main.py`
- `cmd/main.go`, `main.go`
- `src/main.rs`, `lib/main.ex`

**Config** (understand testing and build):
- `jest.config.*`, `vitest.config.*`, `pytest.ini`, `pyproject.toml [tool.pytest]`
- `.github/workflows/*.yml`, `Makefile`, `Taskfile.yml`

If the code graph was built (profile ≥ small), also run:
```bash
python3 .github/tools/codegraph.py stats --db .github/.cache/codegraph.db --json
python3 .github/tools/codegraph.py module . --db .github/.cache/codegraph.db
```

## Step 4 — Write Initial Checkpoint

```bash
python3 .github/tools/memory.py write checkpoint "Initial setup. Profile: [profile]. Project: [name] — [one sentence what it does]. Stack: [stack]. Entry: [main file]. Tests: [test command]. Graph: [status]. No work sessions yet."
```

## Step 5 — Seed Memory (profile ≥ small only)

Skip this step entirely for **tiny** profile.

For **small and above**: extract domain terms from README/docs and write to glossary (3-5 terms max):
```bash
python3 .github/tools/memory.py write glossary "TERM: definition"
```

If README/docs contain non-obvious constraints (security requirements, performance targets, deployment notes), write as learnings:
```bash
python3 .github/tools/memory.py write learnings "insight"
```

## Step 6 — Verify

Run and confirm each check:
```bash
python3 .github/tools/memory.py status
```

- [ ] `.github/config.yaml` has a valid `profile:` value
- [ ] `.github/.cache/memory/checkpoint.md` written
- [ ] `.github/.cache/project-context.md` written
- [ ] Memory status: all kinds within budget
- [ ] `.github/.cache/codegraph.db` exists (skip if tiny profile)

### Daily workflow

```
Start of day  →  /resume           (loads checkpoint + last session)
New task      →  /implement [task]  (just describe it — routing is automatic)
Bug           →  /debug [symptom]
End of day    →  /end-session       (saves state, updates graph, suggests commit)
```

### Routing cheat sheet

| Task type | What happens |
|-----------|-------------|
| Quick fix, single file, ≤30 lines | INSTANT — implements directly, no ceremony |
| New feature with tests, 1-3 files | STANDARD — scope → implement → review |
| Multi-module / refactor / critical-path | DEEP — plan → parallel tasks → validate |
